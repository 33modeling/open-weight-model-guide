# 8×MI300X 192GB — 최고 성능 픽

> 기준일: 2026-08-03 · 명목 VRAM 1.54TB (OAM + Infinity Fabric, ROCm)

## 결론

**GLM-5.2 (753B/40B) — 공식 FP8 755.6GB**가 8×MI300X에서 가장 안전하고 강한 픽이다. MI300X(CDNA 3)는 FP8까지 네이티브 지원하고 ROCm vLLM 스택이 성숙해, 양자화 손실 없는 공식 FP8을 그대로 얹을 수 있다. Kimi K3는 MXFP4 가중치 1,560.9GB로 명목 1.54TB를 넘어 **경계 미달(❌)** — [메모리 산정](../memory-sizing.md)의 판정과 동일하다.

성능 순위상 DeepSeek V4 Pro(864.7GB)가 GLM-5.2보다 위지만, 공식 체크포인트가 FP4+FP8 혼합이라 **CDNA 3의 FP4 미지원**이 걸림돌이다. ROCm용 dequant/INT8 경로가 검증되기 전에는 조건부 픽으로 둔다.

## 순위와 적합성

| 순위(성능) | 모델 | 포맷·가중치 | 8×MI300X 적합성 |
|---:|---|---|---|
| 1 | Kimi K3 (2.8T/104B) | MXFP4 1,560.9GB | ❌ 경계 미달 — runtime 공간 없음 |
| 2 | DeepSeek V4 Pro (1.6T/49B) | FP4+FP8 864.7GB | △ 조건부 — FP4 kernel ROCm 검증 필요 |
| 3 | **GLM-5.2 (753B/40B)** | **공식 FP8 755.6GB** | **◎ 권장 픽 — FP8 네이티브** |
| 4 | Kimi K2.6 / K2.7 Code (1T) | Native INT4 595.2GB | △ ROCm INT4 kernel 확인 후 |
| — | DeepSeek V3.2 | FP8 mixed 689GB | ○ FP8 경로 안전 |
| — | DeepSeek V4 Flash (284B/13B) | FP4+FP8 159.6GB | △ FP4 경로 동일 이슈, FP8 재양자화 시 ○ |

## 용도별 추천

- **최고 품질 단일 서빙**: GLM-5.2 공식 FP8, ROCm vLLM TP=8 — H100 16장 없이 단일 노드로 FP8 GLM을 띄우는 게 이 구성의 최대 장점.
- **V4 Pro가 꼭 필요하면**: FP4 경로의 ROCm 지원(커널·dequant)을 smoke test로 먼저 검증하고 투입.
- **코딩 agent**: K2.7 Code INT4 — CUDA 전용 양자화 커널 비호환 가능성이 있어 [메모리 산정 §CDNA](../memory-sizing.md) 주의사항 확인 후.

## H100 구성 대비 차이

- 16×H100(2노드)이 필요하던 GLM-5.2 FP8·V4 Pro급을 **단일 노드**에 적재할 수 있다 — 노드 간 InfiniBand 불필요.
- 대신 CUDA 전용 kernel·양자화 경로(MXFP4, 일부 GPTQ/AWQ)가 비호환일 수 있어, 포맷 선택지가 FP8/INT8/BF16 중심으로 좁아진다.
- K3는 여기서도 불가 — K3 단일 노드는 8×B300(2.30TB)부터다. ([하드웨어 매트릭스](../hardware-matrix.md))
