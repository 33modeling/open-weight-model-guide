# 16×H100 80GB — 최고 성능 픽

> 기준일: 2026-08-03 · 명목 VRAM 1.28TB (2 nodes, InfiniBand 권장)

## 결론

**DeepSeek V4 Pro (FP4+FP8 864.7GB)**가 16×H100에서 서빙 가능한 가장 강한 오픈웨이트다. Kimi K3는 MXFP4 1,560.9GB로 16×H100(1.28TB)에도 들어가지 않아(16×H200/8×B300급 필요) 여전히 제외된다. 품질 동급 대안으로 **GLM-5.2 공식 FP8(755.6GB)**이 있으며, 8×H100의 W4A8 대비 양자화 손실 없이 서빙할 수 있다.

## 순위와 적합성

| 순위(성능) | 모델 | 포맷·가중치 | 16×H100 적합성 |
|---:|---|---|---|
| 1 | Kimi K3 (2.8T/104B) | MXFP4 1,560.9GB | ✗ 불가 — 16×H200/8×B300급 |
| 2 | **DeepSeek V4 Pro** | **FP4+FP8 864.7GB** | **◎ 권장 픽** |
| 3 | GLM-5.2 (753B/40B) | 공식 FP8 755.6GB | ◎ 대안 픽 — 무손실 FP8 |
| 4 | Kimi K2.7 Code (1T) | Native INT4 595.2GB | ○ 코딩 특화, 권장 구성 |
| — | DeepSeek V3.2 | FP8 mixed 689GB | ○ 구세대, V4 Pro로 대체 |

## 용도별 추천

- **최고 품질 단일 서빙**: DeepSeek V4 Pro, 2노드 TP/PP 분할 — InfiniBand 필수. ([엔진 선택](../engine-selection.md))
- **양자화 손실 없는 GLM**: GLM-5.2 FP8 — 8×H100 W4A8 대비 품질 마진 확보.
- **장기 agent·코딩 운영**: K2.7 Code Native INT4 — 16×H100이 공식 권장 구성이라 context·동시성 여유가 크다.

## 8×H100 대비 무엇이 달라지나

- K2.6/K2.7이 "경계"에서 "권장"으로 — 긴 context·프로덕션 운영 가능.
- GLM-5.2를 W4A8 대신 공식 FP8로, V4 Pro·V3.2 같은 700GB+ 모델이 선택지에 들어온다.
- K3는 여전히 불가 — K3가 목표라면 H200/B300 세대로 넘어가야 한다. ([하드웨어 매트릭스](../hardware-matrix.md))
