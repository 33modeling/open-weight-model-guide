# 8×H100 80GB — 최고 성능 픽

> 기준일: 2026-08-03 · 명목 VRAM 640GB (HGX/DGX NVSwitch)

## 결론

**GLM-5.2 (753B MoE, 활성 ~40B) — 서드파티 W4A8 399.7GB**가 8×H100 단일 노드에서 서빙 가능한 가장 강한 오픈웨이트다. 오픈웨이트 전체 1위인 Kimi K3(HLE 56)는 MXFP4 가중치만 1,560.9GB라 8×H100에는 물리적으로 불가능하고, GLM-5.2(HLE 54.7)가 그다음 급에서 유일하게 여유 있게 들어간다. KV 캐시·긴 context 여유도 약 240GB로 충분하다.

## 순위와 적합성

| 순위(성능) | 모델 | 포맷·가중치 | 8×H100 적합성 |
|---:|---|---|---|
| 1 | Kimi K3 (2.8T/104B) | MXFP4 1,560.9GB | ✗ 불가 — 공식 권장 64 accelerators |
| 2 | **GLM-5.2 (753B/40B)** | **W4A8 399.7GB** | **◎ 권장 픽** |
| 3 | Kimi K2.6 / K2.7 Code (1T) | Native INT4 595.2GB | △ 경계 — 여유 44.8GB, smoke test부터 |
| 4 | DeepSeek V4 Pro | FP4+FP8 864.7GB | ✗ 16×H100 필요 |
| — | Qwen3.5-397B-A17B | FP8 406.2GB | ○ 대안 픽 |
| — | DeepSeek V4 Flash (284B/13B) | FP4+FP8 159.6GB | ◎ 처리량·비용 효율 픽 |
| — | Qwen3-Coder-480B-A35B | INT4 | ○ 코딩 특화 (SWE-bench Verified 69.6%) |

## 용도별 추천

- **최고 품질 단일 서빙**: GLM-5.2 W4A8, vLLM TP=8. ([vLLM 가이드](../serving/vllm.md))
- **처리량·다중 replica**: DeepSeek V4 Flash(284B/활성 13B) FP4+FP8 — 여유 VRAM으로 KV/동시성 확보.
- **코딩 agent**: Qwen3-Coder-480B-A35B 또는 K2.7 Code(경계 구성 유의, [모델 옵션 §K2](../model-options.md) 참고).
