# RTX 4090 실행 가이드

대형 모델 본편은 70B 이상만 다루지만, RTX 4090 한 장에서 실제로 쓸 수 있는 27B~40B uncensored 후보를 이 문서에 예외로 추가합니다.

> 기준: RTX 4090 24GB, CUDA 지원 최신 llama.cpp, 2026-08-04 Hub 파일
>
> 4090 두 장은 총 48GB지만 NVLink가 없으므로 PCIe 분산 비용이 발생합니다.

## 1×RTX 4090

| 우선순위 | 모델 | 선택 파일 | 파일 크기 | 선택 이유 | 시작 context |
|---:|---|---|---:|---|---:|
| 1 | [Qwen3.6-27B Fable Fusion uncensored](https://huggingface.co/DavidAU/Qwen3.6-27B-Fable-Fusion-711-Uncensored-Heretic-NM-DAU-NEO-MAX-MTP-GGUF) | MTP Q4_K_M | 18.50GB | dense 품질과 VRAM 여유의 균형 | 8K~16K |
| 2 | [Qwen3.6-35B-A3B Heretic](https://huggingface.co/SC117/Qwen3.6-35B-A3B-uncensored-heretic-Native-MTP-Preserved-APEX-GGUF) | APEX I-Compact | 17.02GB | 35B total, 3B active MoE | 8K~16K |
| 3 | [Qwen3.6-40B Deckard Heretic](https://huggingface.co/DavidAU/Qwen3.6-40B-Claude-4.6-Opus-Deckard-Heretic-Uncensored-Thinking-NEO-CODE-Di-IMatrix-MAX-GGUF) | IQ3_M | 18.38GB | 한 장에서 가능한 dense 최대급 | 8K |

vision을 쓰려면 각 저장소의 F16/BF16 `mmproj`를 추가로 적재합니다. projector 크기는 27B 0.93GB, 35B 0.90GB, 40B 0.93GB입니다. 텍스트 전용이면 다운로드하지 않는 편이 VRAM에 유리합니다.

### 선택 기준

- **범용·코딩 품질**: 27B MTP Q4_K_M부터 시작합니다. MTP token acceptance가 낮거나 runtime이 MTP를 지원하지 않으면 일반 Q4_K_M 18.05GB로 바꿉니다.
- **생성 속도·agent loop**: 35B-A3B APEX I-Compact를 비교합니다. 업로더의 성능 수치는 DGX Spark 측정이므로 4090 실측값으로 간주하지 않습니다.
- **dense 최대 크기**: 40B IQ3_M을 사용합니다. IQ4_XS는 22.08GB라 projector와 KV cache까지 넣으면 여유가 작아 기본값으로 권장하지 않습니다.

27B 모델 카드는 Heretic ARA로 decensoring했다고 밝히고 자체 시험에서 refusal 4/100, KL divergence 0.0469를 보고합니다. 35B 카드는 Heretic MPOA와 자체 시험 refusal 10/100, KL 0.0015를 보고합니다. 두 수치 모두 업로더 자체 평가이며 독립 검증 결과가 아닙니다.

## 2×RTX 4090

| 우선순위 | 모델 | 선택 파일 | 파일 크기 | 판정 |
|---:|---|---|---:|---|
| 1 | [Llama 3.3 70B Instruct abliterated](https://huggingface.co/bartowski/Llama-3.3-70B-Instruct-abliterated-GGUF) | Q4_K_M | 42.52GB | 범용 품질, 8K·concurrency 1부터 |
| 2 | [DeepSeek R1 Distill Llama 70B abliterated](https://huggingface.co/bartowski/huihui-ai_DeepSeek-R1-Distill-Llama-70B-abliterated-GGUF) | Q4_K_M | 42.52GB | reasoning 우선, 라이선스 이중 확인 |
| 3 | [Qwen3-Next 80B-A3B abliterated](https://huggingface.co/mradermacher/Huihui-Qwen3-Next-80B-A3B-Instruct-abliterated-i1-GGUF) | Q3_K_M | 38.19GB | 전체 크기 대비 낮은 active params |

Llama 계열에서 context 여유가 더 중요하면 Q4_K_M 대신 IQ4_XS 37.90GB를 사용합니다. Qwen3-Next Q4_K_M 48.41GB는 가중치만으로 총 VRAM에 근접하므로 제외합니다.

70B·80B를 두 장에 나누면 PCIe 왕복과 layer 경계 통신 때문에 한 장 모델보다 decode가 느릴 수 있습니다. 동시 처리량이 목적이면 27B 또는 35B를 GPU당 한 복제본씩 띄우는 구성이 더 낫습니다.

## 설치

CUDA backend의 llama.cpp를 설치합니다. 이미 설치되어 있으면 `llama-server --version`만 확인합니다.

```bash
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
cmake -B build -DGGML_CUDA=ON -DLLAMA_CURL=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j
sudo cmake --install build
python -m pip install -U "huggingface_hub[cli]"
```

## 1×4090 다운로드·실행

27B MTP Q4_K_M 텍스트 모델만 받습니다.

```bash
repo='DavidAU/Qwen3.6-27B-Fable-Fusion-711-Uncensored-Heretic-NM-DAU-NEO-MAX-MTP-GGUF'
file='Qwen3.6-27B-Fable-Fus-711-UnHeretic-NM-DAU-NEO-MAX-NEO-MTP-Q4_K_M.gguf'
dir="$HOME/models/qwen3.6-27b-fable"

hf download "$repo" "$file" --local-dir "$dir"
```

```bash
export CUDA_VISIBLE_DEVICES=0
export API_KEY="${API_KEY:?set API_KEY first}"

llama-server \
  --model "$HOME/models/qwen3.6-27b-fable/Qwen3.6-27B-Fable-Fus-711-UnHeretic-NM-DAU-NEO-MAX-NEO-MTP-Q4_K_M.gguf" \
  --alias qwen3.6-27b-fable-q4 \
  --host 127.0.0.1 \
  --port 8080 \
  --api-key "$API_KEY" \
  -ngl 999 \
  --split-mode none \
  --main-gpu 0 \
  --ctx-size 8192 \
  --parallel 1 \
  --flash-attn auto \
  --spec-type draft-mtp \
  --spec-draft-n-max 2 \
  --fit on \
  --fit-target 2048 \
  --jinja \
  --metrics
```

사용 중인 llama.cpp가 MTP 옵션을 지원하지 않거나 token acceptance가 낮으면 일반 Q4_K_M 파일로 바꾸고 `--spec-type`, `--spec-draft-n-max`를 제거합니다. vision이 필요하면 `mmproj-F16.gguf`도 받은 뒤 `--mmproj PATH`를 추가합니다. 그때는 context를 8K로 유지하고 peak VRAM부터 확인합니다.

## 2×4090 다운로드·실행

Llama 3.3 70B Q4_K_M 예시입니다.

```bash
repo='bartowski/Llama-3.3-70B-Instruct-abliterated-GGUF'
file='Llama-3.3-70B-Instruct-abliterated-Q4_K_M.gguf'
dir="$HOME/models/llama-3.3-70b-abliterated"

hf download "$repo" "$file" --local-dir "$dir"
```

```bash
export CUDA_VISIBLE_DEVICES=0,1
export API_KEY="${API_KEY:?set API_KEY first}"

llama-server \
  --model "$HOME/models/llama-3.3-70b-abliterated/Llama-3.3-70B-Instruct-abliterated-Q4_K_M.gguf" \
  --alias llama-3.3-70b-abliterated-q4 \
  --host 127.0.0.1 \
  --port 8080 \
  --api-key "$API_KEY" \
  -ngl 999 \
  --split-mode layer \
  --tensor-split 1,1 \
  --ctx-size 8192 \
  --parallel 1 \
  --flash-attn auto \
  --fit on \
  --fit-target 2048,2048 \
  --jinja \
  --metrics
```

## 적재 확인

```bash
nvidia-smi
curl -fsS http://127.0.0.1:8080/health
curl -fsS -H "Authorization: Bearer $API_KEY" http://127.0.0.1:8080/v1/models
curl -fsS http://127.0.0.1:8080/metrics | head
```

startup log에서 모든 model layer가 GPU에 offload됐는지 확인합니다. CPU offload가 발생하면 매우 느려질 수 있습니다.

## OOM 조정 순서

1. `--ctx-size`를 8192에서 4096으로 내립니다.
2. `--parallel 1`인지 확인합니다.
3. `--fit-target`을 GPU당 3072MiB로 올립니다.
4. 70B Q4_K_M은 IQ4_XS 또는 Q3_K_M으로 내립니다.
5. 40B IQ4_XS는 IQ3_M으로 내립니다.
6. CPU offload는 마지막 수단으로만 사용합니다.

추가적인 멀티 GPU 옵션과 두 복제본 구성은 [기존 llama.cpp 가이드](../serving/llama-cpp.md)를 참고합니다.
